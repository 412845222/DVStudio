# SteamPipe 集成方案 - 调研分析

## 一、项目现状分析

### 1.1 项目架构概览

**DVStudio** 是一款基于 Electron 构建的视频创作 AI 工作流桌面工具，核心架构如下：

| 层级 | 技术栈 | 路径 |
|------|--------|------|
| 前端 | Vue 3 + TypeScript + Vite | `src/` |
| 主进程 | Electron 33.x + Node.js ESM | `electron/main.mjs` |
| 后端 | Node.js IPC 后端（模块化） | `electron/backend/` |
| 本地数据库 | better-sqlite3 | `electron/localdb/` |
| 平台抽象层 | Steam/Mock 提供者 | `electron/platform/` |
| 打包工具 | electron-builder | `package.json#build` |

### 1.3 当前打包流程

**Windows 打包流程：**
```
npm run dist:win
  → scripts/dist-win.mjs
    → vite build（前端构建）
    → electron-builder -w --publish never（NSIS 安装包）
```

**macOS 打包流程：**
```
npm run dist:mac
  → scripts/dist-mac.mjs
    → npm run build（前端构建）
    → electron-builder -m --publish never（ZIP + DMG）
```

**关键配置（package.json）：**
- `asar: true` - 应用代码打包为 asar 归档
- `extraResources` - 额外资源（Python Bridge 脚本、static 目录）
- `win.target: nsis` - Windows 使用 NSIS 安装器
- `mac.target: [zip, dmg]` - macOS 生成 ZIP 和 DMG

## 二、SteamPipe 官方文档调研

### 2.1 SteamPipe 核心概念

根据 [官方文档](https://partner.steamgames.com/doc/sdk/uploading)，SteamPipe 是 Valve 的内容交付系统，核心概念包括：

| 概念 | 说明 |
|------|------|
| **App** | 应用本身，拥有唯一的 AppID |
| **Depot** | 内容仓库，每个 Depot 包含一组文件，可按平台/语言拆分 |
| **Package** | 包，包含一个或多个 Depot，用于销售和授权管理 |
| **Build** | 构建版本，包含多个 Depot 的特定版本 |
| **Branch** | 分支，如 `default`（公开）、`beta`（测试）等 |

### 2.2 关键要求

1. **必须通过 Steam 启动**：`RestartAppIfNecessary` 检查，非 Steam 启动时应重启到 Steam
2. **steam_appid.txt**：必须与可执行文件同目录，包含 AppID
3. **Depot 配置**：每个平台需要独立的 Depot 配置文件（`.vdf`）
4. **Launch Options**：在 Steamworks 后台配置启动参数
5. **Build Account**：需要具有"Edit App Metadata"和"Publish App Changes To Steam"权限的 Steam 账户

### 2.3 打包最佳实践

- 文件被分割为约 1MB 的块，压缩加密后上传
- 更新时只传输变化的块（delta 更新）
- 避免大文件频繁修改，建议限制单个文件大小在 1-2GB
- 不建议对 pack 文件使用通用压缩（Steam 会自动压缩）

## 三、当前项目存在的问题与风险

### 3.1 打包配置缺失

- ❌ 缺少 Steam 版本专用的打包脚本
- ❌ 缺少 SteamPipe 构建配置文件（`.vdf`）
- ❌ 未配置 Steam 版本的额外资源处理

### 3.2 原生模块路径问题

在打包后的环境中，原生模块路径解析可能出现问题：

- 开发环境：`electron/platform/native/win32/`
- 打包环境：`resources/app.asar` 内或 `resources/` 目录下

### 3.3 启动方式问题

- Steam 版本必须通过 Steam 客户端启动
- 需要确保 `steam_appid.txt` 在正确位置
- 需要处理 `RestartAppIfNecessary` 返回 `true` 的情况

### 3.4 多平台支持

当前仅 Windows 有完整的 Steam 原生模块支持，macOS 和 Linux 需要补充。
