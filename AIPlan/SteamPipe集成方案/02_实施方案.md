# SteamPipe 集成方案 - 实施设计

## 一、总体架构设计

### 1.1 设计原则

| 原则 | 说明 |
|------|------|
| **最小侵入** | 不修改现有 Electron 打包流程，新增独立的 Steam 打包脚本 |
| **平台抽象** | 保持现有平台抽象层，Steam 版本仅在打包时增加特定配置 |
| **可配置性** | AppID、DepotID 等配置通过环境变量或配置文件注入 |
| **可回滚** | 任何改动均可通过切换分支回滚，不影响主分支功能 |
| **并行构建** | `dist:steam:win` 是独立的并行构建路径，不修改现有 `dist:win`（NSIS 安装器）流程 |

## 二、详细设计

### 2.1 打包脚本设计

#### 2.1.1 `scripts/dist-steam-win.mjs`

**功能**：生成符合 Steam 上架要求的 Windows 构建产物

**流程**：
```
1. 检查环境变量（STEAM_APP_ID）
2. 构建 DwebSteamJS 原生模块（针对 Electron 33.x）
3. 部署原生模块到 electron/platform/native/win32/
4. 创建/更新 steam_appid.txt
5. 执行 vite build（前端构建）
6. 执行 electron-builder（生成 portable 版本，无安装器）
7. 将构建产物整理到 steam-pipe/content/ 目录
```

**关键配置差异**：

| 配置项 | 普通版本 | Steam 版本 |
|--------|----------|------------|
| `target` | `nsis`（安装器） | `dir`（便携式目录） |
| `asar` | `true` | `true` |
| `asarUnpack` | 无 | `electron/platform/native/**`（原生模块必须从 asar 中解压） |
| `extraResources` | Python Bridge 脚本 | 增加 Steam 原生模块 |
| `output` | `release-<timestamp>` | `steam-pipe/build/win64-unpacked` |

**electron-builder --dir 输出结构**：
```
steam-pipe/build/win64-unpacked/
├── DVStudio.exe
├── resources/
│   ├── app.asar
│   ├── app.asar.unpacked/
│   │   └── electron/platform/native/win32/
│   │       ├── dweb_steamjs.node
│   │       └── steam_api64.dll
│   ├── python-bridge-scripts/
│   ├── static/
│   └── runtime/
└── [其他系统文件]
```

**后处理整理结构（SteamPipe 期望）**：
```
steam-pipe/content/win64/
├── DVStudio.exe
├── resources/
│   ├── app.asar
│   ├── app.asar.unpacked/
│   │   └── electron/platform/native/win32/
│   │       ├── dweb_steamjs.node
│   │       └── steam_api64.dll
│   ├── python-bridge-scripts/
│   ├── static/
│   └── runtime/
└── steam_appid.txt（仅开发测试用，不上传到 depot）
```

**核心代码逻辑**：
```javascript
// 1. 构建原生模块
await run('npm', ['run', 'build:electron'], { cwd: 'DwebSteamJS' })

// 2. 部署原生模块
await run('node', ['scripts/setup-steam-native.mjs'])

// 3. 前端构建
await run('npx', ['vite', 'build'])

// 4. Electron 打包（便携式目录，使用 asarUnpack 解压原生模块）
//    注意：仅使用 asarUnpack，不使用 extraResources 复制原生模块，避免冗余
await run('electron-builder', [
  '--dir',
  '-w',
  '--publish', 'never',
  '--config.directories.output', 'steam-pipe/build/win64-unpacked',
  '--config.asarUnpack', 'electron/platform/native/**',
  '--config.extraResources', JSON.stringify([
    { from: 'electron/backend/python-bridge/scripts', to: 'python-bridge-scripts' },
    { from: 'electron/static', to: 'static', filter: ['**/*', '!runtime/**'] },
    { from: 'electron/static/runtime', to: 'runtime' }
  ])
])

// 5. 后处理：整理构建产物到 steam-pipe/content/win64
const unpackedDir = 'steam-pipe/build/win64-unpacked'
const contentDir = 'steam-pipe/content/win64'
fs.rmSync(contentDir, { recursive: true, force: true })
fs.cpSync(unpackedDir, contentDir, { recursive: true })

// 6. 开发测试用：复制 steam_appid.txt 到构建目录（不上传到 SteamPipe）
//    Steam 启动时会自动提供 steam_appid.txt，不需要包含在 depot 中
fs.writeFileSync(path.join(contentDir, 'steam_appid.txt'), process.env.STEAM_APP_ID || '480')
```

#### 2.1.2 `scripts/upload-steam.mjs`

**功能**：调用 steamcmd 将构建产物上传到 SteamPipe

**流程**：
```
1. 读取环境变量（STEAM_USERNAME, STEAM_PASSWORD, STEAM_APP_ID）
2. 验证构建产物是否存在
3. 生成实际的 .vdf 配置文件（替换占位符）
4. 调用 steamcmd 执行构建上传
5. 解析输出，检查是否成功
```

**核心代码逻辑**：
```javascript
// 1. 环境变量验证
const requiredEnv = ['STEAM_APP_ID']
requiredEnv.forEach(key => {
  if (!process.env[key]) throw new Error(`Missing ${key}`)
})

// 2. 生成配置文件（替换占位符）
const vdfTemplate = fs.readFileSync('steam-pipe/app_build.vdf', 'utf8')
const vdfContent = vdfTemplate
  .replace('{{APP_ID}}', process.env.STEAM_APP_ID)
  .replace('{{BUILD_OUTPUT}}', 'steam-pipe/output')
  .replace('{{VERSION}}', pkg.version)

fs.writeFileSync('steam-pipe/app_build_generated.vdf', vdfContent)

// 3. 调用 steamcmd（支持 Steam Guard 2FA）
//    steamcmd 登录格式：+login <username> <password> <steam_guard_code>
//    如果账户启用了 Steam Guard，需要提供 steam_guard_code
//    首次登录后会生成 Sentry 文件，后续登录不需要验证码（除非安全设置变更）
const steamcmdPath = 'SteamworksSDK/sdk/sdk/tools/ContentBuilder/builder/steamcmd.exe'
const loginArgs = ['+login']
if (process.env.STEAM_USERNAME) loginArgs.push(process.env.STEAM_USERNAME)
if (process.env.STEAM_PASSWORD) loginArgs.push(process.env.STEAM_PASSWORD)
if (process.env.STEAM_GUARD_CODE) loginArgs.push(process.env.STEAM_GUARD_CODE)

await run(steamcmdPath, [
  ...loginArgs,
  '+run_app_build', 'steam-pipe/app_build_generated.vdf',
  '+quit'
])
```

**Steam Guard 2FA 处理方案**：

| 场景 | 方案 | 说明 |
|------|------|------|
| 首次登录 | 手动输入验证码 | 运行脚本时设置 STEAM_GUARD_CODE 环境变量 |
| 后续登录 | 使用 Sentry 文件 | steamcmd 首次成功登录后会在用户目录生成 Sentry 文件 |
| CI/CD 环境 | 使用专用构建账户 + 手机验证码 | 或使用 steamcmd 的 `-remember_password` 参数 |
| 无法自动化 | 手动上传 | 在 Steamworks 后台手动上传构建 |

**注意**：
- 启用 Steam Guard 的账户在安全设置变更后（如更换邮箱、手机号），需要等待 3 天才能设置构建上线
- 建议创建专用的构建账户，仅授予"Edit App Metadata"和"Publish App Changes To Steam"权限
- steamcmd 登录失败时会提示验证码要求，脚本应捕获并提示用户提供

### 2.2 SteamPipe 配置模板设计

#### 2.2.1 `steam-pipe/app_build.vdf`

```vdf
"appbuild"
{
	"appid" "{{APP_ID}}"
	"desc" "DVStudio {{VERSION}} (Steam Release)"
	"buildoutput" "{{BUILD_OUTPUT}}"
	"contentroot" "steam-pipe/content"
	"setlive" "beta"
	"preview" "0"
	"local" "0"
	"depots"
	{
		"{{DEPOT_ID_WIN}}" "depot_build_win.vdf"
		"{{DEPOT_ID_MAC}}" "depot_build_mac.vdf"
		"{{DEPOT_ID_LINUX}}" "depot_build_linux.vdf"
	}
}
```

**占位符说明**：
- `{{APP_ID}}`：Steam 应用 ID
- `{{VERSION}}`：应用版本号（从 package.json 读取）
- `{{BUILD_OUTPUT}}`：构建输出目录
- `{{DEPOT_ID_WIN}}`：Windows Depot ID
- `{{DEPOT_ID_MAC}}`：macOS Depot ID
- `{{DEPOT_ID_LINUX}}`：Linux Depot ID

#### 2.2.2 `steam-pipe/depot_build_win.vdf`

```vdf
"depotbuild"
{
	"depotid" "{{DEPOT_ID_WIN}}"
	"contentroot" "steam-pipe/content/win64"
	"depotfrommanifest" "0"
	"filemapping"
	{
		"local" "."
		"depot" "."
	}
	"ignore"
	{
		"*.pdb"
		"*.bak"
		"*.log"
		"node_modules/"
		"steam_appid.txt"
	}
}
```

**注意**：`steam_appid.txt` 被排除在 depot 之外，因为：
- Steam 客户端启动应用时会自动在工作目录创建 `steam_appid.txt`
- 包含在 depot 中可能会覆盖 Steam 提供的文件，导致冲突
- 开发测试时需要手动创建 `steam_appid.txt`（已在打包脚本中处理，仅用于本地测试）

### 2.4 原生模块打包配置

**问题分析**：

当前 `package.json#build.extraResources` 不包含 Steam 原生模块，导致打包后无法加载 Steamworks SDK。

**解决方案**：

在 Steam 打包脚本中动态扩展 `extraResources`：

```javascript
const extraResources = [
  {
    from: 'electron/backend/python-bridge/scripts',
    to: 'python-bridge-scripts'
  },
  {
    from: 'electron/static',
    to: 'static',
    filter: ['**/*', '!runtime/**']
  },
  {
    from: 'electron/static/runtime',
    to: 'runtime'
  },
  {
    from: 'electron/platform/native/win32',
    to: 'platform/native/win32'
  }
]
```

**运行时路径解析**：

修改 `electron/platform/providers/steam.mjs` 中的路径解析逻辑：

```javascript
function getNativeWin32Dir() {
  if (app.isPackaged) {
    const unpackedPath = path.join(process.resourcesPath, 'app.asar.unpacked', 'electron', 'platform', 'native', 'win32')
    if (fs.existsSync(unpackedPath)) {
      return unpackedPath
    }
    console.warn('[platform:steam] Native module directory not found at:', unpackedPath)
    return process.resourcesPath
  }
  return path.join(__dirname, '..', 'native', 'win32')
}
```

**路径说明**：
- 仅使用 `asarUnpack` 解压路径：`resources/app.asar.unpacked/electron/platform/native/win32`
- 不使用 `extraResources` 复制原生模块，避免文件冗余
- 开发环境（非打包状态）使用 `electron/platform/native/win32/` 路径

**测试建议**：在实施路径解析逻辑前，先执行一次测试打包：
```bash
npm run build
npx electron-builder --dir -w --config.asarUnpack="electron/platform/native/**"
```
然后检查输出目录中的实际路径结构，确保代码中的路径与实际输出一致。

### 2.5 GitHub Actions 工作流设计

#### `.github/workflows/steam-build.yml`

**触发条件**：
- 手动触发（workflow_dispatch）
- 推送标签（v*）

**环境变量**：
- `STEAM_USERNAME`：GitHub Secrets
- `STEAM_PASSWORD`：GitHub Secrets
- `STEAM_APP_ID`：GitHub Secrets
- `STEAM_DEPOT_ID_WIN`：GitHub Secrets

**步骤**：
```yaml
1. Checkout 代码
2. 设置 Node.js 环境
3. 安装依赖
4. 构建 DwebSteamJS 原生模块
5. 运行 dist:steam:win 打包
6. 保存构建产物为 Artifact（供手动上传）
7. 尝试自动上传（可选，需要 Steam Guard 2FA 已解决）
8. 保存构建日志
```

**Steam Guard 2FA 限制**：
- GitHub Actions 环境中无法自动处理 Steam Guard 验证码
- 解决方案：
  1. 在首次运行时手动提供验证码，生成 Sentry 文件后缓存到 GitHub Cache
  2. 使用专用构建账户，在本地首次登录生成 Sentry 文件后上传到 Secrets
  3. 放弃自动上传，仅自动构建，手动在 Steamworks 后台上传
- 建议初期采用方案 3（手动上传），待 2FA 问题解决后再启用自动上传

## 四、风险评估

### 4.1 技术风险

| 风险 | 等级 | 应对措施 |
|------|------|----------|
| 原生模块 ABI 不兼容 | 高 | 使用 Electron 版本对应的 node-gyp 构建 |
| asar 打包导致原生模块无法加载 | 高 | 使用 `asarUnpack` 将 `electron/platform/native/**` 从 asar 中解压 |
| steamcmd 认证失败（Steam Guard 2FA） | 高 | 使用专用构建账户，首次登录提供验证码生成 Sentry 文件；CI/CD 初期采用手动上传 |
| 构建产物过大 | 中 | 清理不必要文件，使用 asar 压缩 |
| 多平台差异 | 中 | 分别构建，使用平台特定配置 |
| 运行时路径解析错误 | 中 | 在打包脚本中同时使用 asarUnpack 和 extraResources，运行时按优先级查找；先做测试打包确认路径 |

### 4.2 业务风险

| 风险 | 等级 | 应对措施 |
|------|------|----------|
| Steamworks 后台配置错误 | 高 | 仔细核对 AppID、DepotID、Launch Options |
| 版本冲突 | 中 | 使用分支管理（beta 分支测试） |
| 审核失败 | 中 | 提前准备测试，确保符合 Steam 上架要求 |

## 五、验证方案

### 5.1 本地验证

**Windows Steam 版本验证步骤**：

1. 设置环境变量：`set STEAM_APP_ID=480`
2. 运行打包脚本：`npm run dist:steam:win`
3. 检查输出目录 `steam-pipe/content/win64/`：
   - ✅ `DVStudio.exe` 存在
   - ✅ `resources/app.asar` 存在（应用代码归档）
   - ✅ `resources/app.asar.unpacked/electron/platform/native/win32/dweb_steamjs.node` 存在（asarUnpack 解压的原生模块）
   - ✅ `resources/app.asar.unpacked/electron/platform/native/win32/steam_api64.dll` 存在
   - ❌ `resources/platform/native/` 不存在（不应通过 extraResources 复制，避免冗余）
   - ⚠️ `steam_appid.txt` 存在（仅开发测试用，不上传到 SteamPipe）
4. 启动 Steam 客户端，运行 SpaceWar（AppID 480）测试环境
5. 运行构建产物，检查 Steam 集成是否正常

### 5.2 上传验证

**上传流程验证步骤**：

1. 设置环境变量：`STEAM_USERNAME`, `STEAM_PASSWORD`, `STEAM_APP_ID`
2. 运行上传脚本：`npm run upload:steam`
3. 检查 `steam-pipe/output/` 日志：
   - ✅ 无错误信息
   - ✅ 显示"Success!"
4. 登录 Steamworks 后台，检查构建是否出现在"Builds"页面
5. 设置为测试分支，测试下载和安装

## 七、注意事项

### 7.1 AppID 管理

- 开发阶段使用 SpaceWar AppID（480）进行测试
- 正式上架前需要申请正式 AppID
- `steam_appid.txt` 必须与可执行文件同目录

### 7.2 原生模块构建

- 必须使用与 Electron 版本匹配的 node-gyp 配置
- 命令：`npm run build:electron`（在 DwebSteamJS 目录）
- 构建产物必须复制到 `electron/platform/native/win32/`

### 7.3 Steam 启动要求

- Steam 版本必须通过 Steam 客户端启动
- `RestartAppIfNecessary` 在非 Steam 启动时会返回 `true`
- 开发环境通过环境变量 `ELECTRON_DEV` 跳过此检查

### 7.4 内容大小限制

- 单个 Depot 建议不超过 2GB
- 大文件会影响更新速度
- 建议将 Python 运行时等大文件放在单独的 Depot
